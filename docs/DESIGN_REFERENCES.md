# Northstar OR: institutional interface references

Research date: **2026-10-24**. The owner asked for medical institutional software rather than a generic AI SaaS aesthetic. This study distinguishes public product observations from proposed Northstar decisions. Marketing claims and screenshots are not independent usability evidence or proof that Northstar is clinically effective.

No vendor screenshot, logo, clinical image, patient display or UI asset is added to the app or brand kit. Follow links to inspect the originals; Northstar keeps its own artwork and implementation.

## 2. The direction: a clinical operations workspace

Our design judgment is to organize the app around **cases, people, recorded state and accountable actions**. The user should recognize the current site/case, support arrangement, unresolved work and action result without reading a promotional headline.

| Northstar decision | Implementation consequence | How to verify |
| --- | --- | --- |
| Worklist before dashboard | Planner uses aligned case rows, useful schedule/status filters, a selected detail and explicit New case; no wall of KPI tiles | Find and open a case; compare two rows; empty list offers creation |
| Persistent context | A compact header identifies workspace/site, case, named support role/state, unresolved count and actual communication mode | Case/recipient remain clear after tab changes, reply arrival, keyboard and narrow layout |
| Task-focused Co-pilot | Progress/current work/activity regions; the current item gets space, warning has a named action | Record/defer/ack/correct by touch without a chat conversation |
| Anchored controls | Consequential actions stay in predictable locations, expand for text and remain keyboard-safe | Long question/recipient, enlarged text and window resize preserve reachability |
| Restrained hierarchy | Neutral system type, practical labels, left-aligned information, quiet dividers, modest logo and 6/10/12 pt radii | Compare screens for consistent alignment/spacing; no oversized promotional heading or excessive nesting |
| Semantic status | Icon + factual text; selection blue, recorded confirmation green, unresolved amber, failed app action red | Explain state without color; acceptance/connection/receipt remain distinct |
| Forms that do work | Workspace/contact/case forms have labels, validation, Save/Cancel, retained drafts and visible persistence outcomes | Blank setup and a new case work without source edits or sample IDs |
| Quiet communication | The team's question, immutable snapshot and reply/receipt history are primary; optional AI drafts stay secondary | Recipient can identify question/unresolved items and reply without reading unrelated analytics |

The approved dark navy remains the initial app theme. Public examples show different treatments for different jobs; none proves that dark or light is inherently more clinical. Verify our contrast and in-room/projected readability. A later light-theme decision should follow workflow/device feedback rather than an untested claim that hospitals require one palette.

## 3. What makes Northstar recognizable

Keep the connected ice-blue star/pulse mark modest in the shell. Build distinctiveness through an unusually clear **support handoff**: current plan and named role → team's question → selected context/unresolved work → explicit recipient acknowledgment → reply → retained review record.

Use a compact support-status strip in the case header and an unresolved-item summary that links to the actual records. The shared case identity and communication state remain in the same position across destinations. These are purposeful product signatures; the logo does not need to be repeated on every card.

Planner emphasizes logistical constraints for rural support; Co-pilot emphasizes team-reported state; Remote Support emphasizes joining with context. That distinction creates a coherent app without copying another vendor's screens.

## 4. Patterns to exclude

- AI-chat or prompt composer as the app's home screen; “Ask anything” as the main workflow.
- Decorative gradients, glows, glass panels, orbs, animated sparkles, flashing borders and large rounded promotional typography.
- A collection of disconnected cards, fabricated readiness/health scores, fake activity graphs or vanity counters.
- Bright pills around every value, icon-only consequential actions, unlabeled color dots, or patient-monitor-like waveforms without measured data.
- Huge empty hero areas that displace records; tiny dense desktop rows copied onto an iPad without adaptation.
- Fake login, “Live,” verified identity, delivery, receipt or hospital-integration indicators unsupported by the implementation.

## 5. Validation that earns the professional claim

Use DESIGN.md for the measurable type, contrast, input and layout rules. Reference products inform hypotheses; our own evidence must come from tasks on Northstar:

1. Configure a fictional workspace and create a new case without assistance or seed data.
2. Find the current case, selected plan, recipient and unresolved item after a context switch.
3. Explain requested, accepted, disconnected, received and acknowledged states correctly.
4. Send a question, recover from failure, correct a record, relaunch and resume without losing context.
5. Perform the core actions at enlarged text with touch/keyboard/VoiceOver and without relying on motion or color alone.

Record observed errors, hesitation, time to find information and recovery success. Review fictional walkthroughs with OR staff/coordinators/device reps when available. Do not call the design “proven” because a well-known vendor uses a similar visual pattern; a usable institutional product requires its own evidence.

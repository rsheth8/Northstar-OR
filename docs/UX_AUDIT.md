# Northstar OR: whole-product UX audit

**Reviewed October 25, 2026. Baseline: `21b107b` (PR #47).** This is an expert inspection and simulator walkthrough, with proposed changes. It does not claim that these changes shipped or that OR staff validated the design. Keep DESIGN.md as the canonical guide. [PR #48](https://github.com/rsheth8/Northstar-OR/pull/48) separately addresses calls staying alongside the workspace; do not duplicate that implementation.

## Judgment

The app has useful working foundations: ordinary setup and case forms, explicit recording actions, pinned deferrals, retained records, contextual questions and honest local-delivery labels. The light surfaces, native navigation and restrained identity are worth retaining.

It still feels assembled from several feature demonstrations. The user has to reconcile repeated headings, multiple ways to communicate, two different role concepts and several versions of the same case context. The main polish work is reducing that interpretation and making interruption/recovery predictable.

The strongest observed failure is the enlarged-text shell. At accessibility XXXL, Co-pilot's work scroller begins at **y=613.5 in a 1032 pt window**. Only 418.5 pt remain for the task. The confirmation button begins at y=1343 before scrolling. Workflow titles clip inside fixed-size tiles. The action becomes hittable after scrolling, which passes a reachability assertion but fails the intended quick-use experience. See [initial state](evidence/ux-audit/16-copilot-accessibility5.png), [scrolled action](evidence/ux-audit/17-record-action-accessibility5.png) and their retained hierarchies.

## The people and moments to design for

These are design hypotheses for fictional walkthroughs, not claims about interviewed users.

| User / moment | The interface must answer | Design consequence |
| --- | --- | --- |
| Room team member returning after an interruption | Which case am I recording? What is selected? What remains unresolved? | Stable case context, dominant current item, persistent named warning and explicit action result. Avoid making the user reconstruct state from a transcript. |
| Coordinator comparing cases | Which day/site? What coverage constraint? Is this browsing or recording? | Date grouping, readable rows, independent recording state and an explicit start/resume action. |
| Technical rep joining late | What exactly is the team asking? Which case? What has changed? | Exact question and acknowledge/reply first, original request context beside it, current updates separately labeled. |
| Either participant during a link failure | What was saved? What reached the other device? What should I retry? | Separate save, transport receipt and human acknowledgment; retain the same draft/message identity; put retry beside the failed action. |
| Person configuring the workspace | What does this field mean? Did my change save? Can I leave safely? | Persistent field labels, local validation, clear Save/Cancel behavior and protection for changed drafts. |

FDA's human-factors overview explicitly considers users, environments and interfaces, including lighting, noise and distractions. That supports designing for interruptions and visible feedback; it does not establish Northstar's regulatory status or usability. [FDA: Human Factors Considerations](https://www.fda.gov/medical-devices/human-factors-and-medical-devices/human-factors-considerations).

AHRQ's handoff guidance emphasizes clear information, receiver acknowledgment and opportunities to question/review. Northstar can apply these communication principles to technical coordination; the app does not transfer clinical authority to a rep. [AHRQ: Handoff](https://www.ahrq.gov/teamstepps-program/curriculum/communication/tools/handoff.html).

## Findings, in fix order

**High** means substantial workflow friction, ambiguity or lost-work exposure. **Medium** means repeated scanning, weak discoverability or unfinished presentation. Priorities describe this prototype's UX, not a clinical hazard classification. Evidence marked **source** was inspected in code rather than exercised as a user task.

## What each finished page should do

| Page | First visible content | Primary action | Completion / recovery behavior |
| --- | --- | --- | --- |
| Setup | Fictional-workspace scope; short labeled workspace/site/participant fields; stated role | Create workspace | First invalid field is explained and focused. Sample path remains explicit. On success open useful Planner empty state with Create first case. |
| Workspace settings | Workspace/site summary; participant role and device role clearly separated; contacts entry | Save settings | Saved baseline updates, errors retain edits, closing a changed draft explains discard. Contacts saved in nested navigation must survive settings save. |
| Contact directory / editor | Name, stated technical/clinical role, capability, directory availability | Add / Save contact | Return to a visibly updated row. Unknown travel remains blank/unknown. Removal explains impact; Back protects edits. |
| Planner | Day-grouped cases with schedule/site, coverage risk and recording state; active recording context distinct from selection | New case; selected case Start / Resume / Open Co-pilot | Opening a record is explicit. Pending acknowledgment explains a blocked switch without blocking browsing. Unsupported templates explain why recording is unavailable. |
| New / edit case | Reference/title labels; configured site; site-local date/time and duration; supported template | Save case | Correct date-specific time-zone label, duplicate validation at field, failure retains entries. Cancel/swipe protect edits. New case becomes selected without silently starting. |
| Co-pilot | Case/site + unresolved; current item and recorded state; relevant warning/action | Record confirmation **or** Acknowledge deferral | Recorded result persists; item navigation stays explicit. Deferral remains unresolved after acknowledgment. Support/correction/review stay available while pinned. |
| Request support | Case/current item; chosen technical rep + directory state + actual peer; team's question | Send question | Snapshot meaning is inspectable; draft retained on failure; original message retry is visible; delivery and acknowledgment remain distinct. |
| Remote Support | Exact latest actionable question, sender/time and acknowledgment; compact case identity | Acknowledge question, then Send reply | Original request snapshot remains frozen; current changes appear separately. New question/reply is prominent without jumping a reader's scroll. Failure is beside the action. |
| Connect / call | Actual link/peer state and one next connection action; call invitation separately | Find/Invite/Accept device, then Request/Accept call as applicable | Mic/camera permissions explain a next step. Ending call keeps case link when supported. Lost link changes the displayed state. Consume #48's docked/adaptive call panel and test media controls on real devices. |
| Record review / correction | Correct case/session; unresolved first; original recorded state, actor and time | Review; explicitly Save correction | Original event remains visible. Correction never silently implies clinical completion. Full history and support exchange remain attached to that case after relaunch. |

## Delivery sequence

Keep each row a separate task/branch/PR with the named files reserved before work. These are proposals, not active code claims.

1. **Shared shell and accessibility:** NorthstarWorkspaceChrome, RootView and focused shell UI tests. Coordinate after PR #48 merges; no call engine or domain rewrite. Fix UX01/04 and expose direct empty-state routes through existing destination state.
2. **Forms and exits:** workspace settings/contact/setup, followed by a separate Planner case-form slice. Persistent labels, dirty-draft guards, useful validation and visible save actions. Reuse existing persistence and form validation. Fix UX02/09/14.
3. **Planner clarity:** day/record-state rows, applied-filter summary, unsupported-template explanation and concise logistical detail. Fix UX03/12/15. Keep named plan/acceptance implementation separate.
4. **Co-pilot focus:** remove duplicate hierarchy, adaptive workflow navigation, one support entry and clearer warning/correction presentation. Fix UX06/08/10. Keep domain guards and retained drafts intact.
5. **Rep support:** question-first adaptive brief/conversation, distinct frozen/current context, anchored compose/error/retry and new-message attention. Fix UX05/07/13 with separately coordinated shared eligibility changes if needed.
6. **Retained review:** unresolved-first review and explicit correction comparison. Fix UX11 and test the correct case after switching/relaunch.

## Evidence and gates

The [evidence index](evidence/ux-audit/README.md) records device, text sizes, captures and actual runs. Five simulator checks passed (three new walkthrough checks and two existing support checks). The new checks cover: the whole-product route, largest-text action reachability/rep empty state, and a contact edit surviving a later settings save. The suspected stale-contact overwrite **did not reproduce** and is not a finding. Do not convert that hypothesis into a bug claim.

The acceptance tests for implementation should include:

- Returning after an interruption: identify case, selected item and unresolved work without reopening history. Proposed moderated target: within five seconds; not measured in this audit.
- One explicit record/defer/ack/correct loop at default and enlarged text, retaining the pending gate through every input path.
- Two days/two cases: browse, start/resume, switch and relaunch; preserve records and drafts. No sample-name dependency.
- Two devices: correct recipient/peer context; send → actual receipt → human acknowledgment → reply; disconnect/retry without duplicate messages or false “received.”
- Dirty forms: toolbar Cancel/Done, Back, swipe-dismiss and keyboard exit; save failure retains entries and focuses a useful recovery action.
- Native keyboard, VoiceOver reading/focus, Reduce Motion and physical touch in a fictional walkthrough. These checks remain unrun here. A 72 pt design token or a hittable automated element alone does not prove physical usability.

Review the revised fictional workflow with an OR team member/coordinator and a technical rep before calling it intuitive for those populations. Capture hesitation, wrong-state interpretation, missed messages and recovery difficulty. The goal is fewer decisions, predictable outcomes and visible accountability; this audit establishes specific work to get there.
